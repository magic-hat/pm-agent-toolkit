# PRDs and product briefs

Briefs, PRDs and their companion files: prototype links, eval plans and launch checklists.

## File names

`<product> - <feature>.md`. A companion file uses the same prefix, for example `<product> - <feature> - evals.md`.

## Front matter

Use the 7 fields in `AGENTS.md`. These rules apply in this folder:

- `status`: draft, in review, approved, shipped or archived.
- `product`: required.

## Rules for this folder

- Start each PRD from `_templates/prd.md`.
- In a brief, write the problem and how to measure success before you write the solution.
- Link the evidence (customer feedback, metrics) in `related`.
- Keep the decision log at the end of the note.
- If the user shares the note outside the vault, use `_skills/share-doc`. The skill keeps `linked-resources.md` current.
